## 3. 위험

- `.st-key-*`·`data-testid` 셀렉터는 Streamlit 버전에 묶임 → **P1-4 버전 고정 선행**. 셀렉터 불일치는 조용히 실패 → 정적 테스트 + 스크린샷으로 확인.
- success→flash 치환 65곳 중 일부는 rerun 이 "목록 갱신" 목적 — flash 로 바꿔도 rerun 은 유지(메시지만 다음 실행으로). 제거하는 것은 `st.success` 호출이 아니라 **메시지 유실**.
- 수기 수주 행 삭제는 세션 리스트 조작 — 저장 중복 검사(7098)와 `m_so_no` 유지 규칙 그대로.
- 휴대폰 사이드바 정렬은 Streamlit 오버레이 DOM 차이[추정] → 셀렉터를 넓혀서(`section[data-testid="stSidebar"] button`) 적용 후 375 확인.

### 3-1. 구현 중 변경 (개발 세션, 2026-10-26 — 커밋 9c7353f·a53dfbc·82929db, 상세는 리뷰 패키지 `_UIUX_U0U1_리뷰패키지_20261026_risks_flash.md` §G)

1. **위험 버튼 셀렉터**: Streamlit 1.66.1 은 `st-key-<key>` 클래스 뒤에 emotion 클래스 2개를 붙여 `[class$="_del"]` 끝 매칭이 안 된다(실측). `danger_` 접두 규칙은 기존 위젯 key 를 바꿔야 해서 "key 변경 금지"와 충돌 → **"접미+공백"(`[class*="_del "]`) 과 끝 매칭(`$=`) 병행**으로 바꿨다(key 변경 없음).
2. `po_pending_cancel`("취소 (기존 품목 유지)")은 `_cancel` 로 끝나지만 안전한 선택이라 위험색 제외 목록에 넣었다.
3. 수기 수주 행 삭제 key 를 `so_item_{i}_del` 로(계획의 `so_item_del_{i}` 는 접미 규칙에 안 걸림).
4. U1b ④: 계획이 지목한 `st.warning(READONLY_MSG)` 2곳은 서로 다른 세부(오늘 루틴·템플릿 관리)라 그대로 두고, 오늘 루틴에서 실제로 겹치던 두 번째 안내(`ensure_cards` 의 읽기 모드 msg)를 읽기 모드일 때 숨겼다.
5. 관리자 4화면(마스터 관리·생산 보고·영업 보고·원가 확인)은 `nav_page_head` 를 안 불러 flash 가 다음 사용자 화면으로 새므로 제목 아래 `nav_flash_show()` 를 신설했다.
6. 1.66 은 사이드바 메뉴가 **데스크톱도** 가운데 정렬(버튼 안쪽 flex 래퍼) → 모든 폭에서 왼쪽 정렬로 고쳤다.
7. 헤더 구분선은 CSS 가 아니라 코드 1줄(`st.divider()`) 제거. 375 에서 한 줄 유지를 위해 제목 19px.
8. 위험 버튼 규칙 밖 파괴 버튼 7곳(BOM 행 삭제·삭제 확정·이 날짜 삭제·입고 취소·모두 초기화·표 비우기·판독 결과 비우기)은 key 변경 금지라 이번에 색 미적용 — U3 후보.
