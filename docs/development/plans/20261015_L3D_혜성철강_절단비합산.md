## 배경·원인

- 시트 시절 Apps Script `product_master_library.gs` v1.0(2026-04-23) `PMLib.preprocessHyesungCutting`: 같은 날짜 혜성철강 "환봉/단조/육환봉"
  행 다음의 "절단비" 행을 한 줄로 합산(수량 = 절단비 수량 = 부품 수, 금액 = 환봉+절단비, 개당 단가 = 합산 금액 ÷ 부품 수, 비고 "[+절단비 N원]").
  v11 의 자재_개당단가(= `products.material_unit_price`)가 이 규칙으로 산출됐다.
- 2026-05 매입 동기화를 앱(`utils/purchase_sync.py`, 841dde8)으로 옮기면서 이 전처리가 빠졌다. 동기화는 장부 행을 그대로 넣고, 매칭은 KG 행을 보류·
  절단비 행을 '소재 아님'으로 버린다. `purchase_ledger.kg_price/ea_price` 는 6,544행 모두 NULL.

  단가로** 쓰여 4DI0622A4-5M-1 소재비 1,650원(판매가 998원) 같은 오류.
- 재질 인식도 SCM415(H)/SCM420(H)/S20C 를 모르므로(`norm_grade`) 합산해도 디아이씨 소재가 매칭되지 않음 → 같이 확장.

## L2 코드 (동기화 이식, 장부 재처리보다 먼저 배포)

- `utils/purchase_sync.merge_cutting_rows(rows)`: 위 규칙 그대로(순수 함수, 입력 불변). 조건: 혜성 업체·환봉/단조/육환봉·다음 행이 같은 날짜·혜성·'절단'·절단 수량>0.
  합산 행: unit EA, qty 절단 수량, weight 는 환봉 kg 유지, unit_price round((환봉 공급가+절단비 공급가)/수량), amount/vat/total 합, remark += "[+절단비 N원]",
  `_merged_from` 에 절단비 행(장부 재처리용, 동기화 저장 전 제거).
- `norm_grade`: `SCM\d{3}H?` → SCM415/SCM420/SCM440(종전 동일), `S\d{2}C` → S45C(종전 동일)/S20C, 303.
- 동기화 ① 미리보기: 탭별 `parse_month_tab` → `merge_cutting_rows` → 중복 검사·매칭(합산 행은 EA·단가>0 이라 치수 매칭 대상). 안내 문구·합산 건수 표시.
- v2(Reviewer 반영): 합산 멱등(비고 '[+절단비' 있으면 재합산 안 함)·날짜 필수·절단비 행의 matched_pn/비고 승계·환봉 kg 단가 `kg_price`/개당 `ea_price` 보존(동기화 payload 포함)·`norm_grade` 는 종전 `in` 판정과 같게 앞 글자 무관(S45C)·303 은 뒤에 숫자 없을 때만·자재 조회 페이지네이션(활성 927).
- 테스트 `tests/test_purchase_sync.py` +4 (실데이터 쌍 302원·kg/ea, 가드 4종, 멱등·인접·통봉 EA·승계·중복 키 동일성, 재질 확장 회귀). 14 passed.
