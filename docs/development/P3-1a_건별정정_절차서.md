# P3-1a 건별 정정 절차서 — 새 함수가 거부하는 옛 전표 12장 (2026-11-06)

`revise_shipment`(082)는 기록이 불완전한 옛 전표 라인의 정정·취소를 **거부**한다(계획서 v3 §4-5 · §17 결정 2).
실제로 그 전표를 바꿔야 할 때만 이 절차로 **그 전표 하나씩** 데이터 정정(L3-D)을 한다. 일괄 처리하지 않는다.

화면은 전표를 열 때 `revise_shipment_check` 로 해당 라인과 이유를 보여 주고 그 라인 편집·전표 취소를 잠근다.

## 공통 절차(L3-D)
1. 담당자에게 받는 것: 전표번호 · 원하는 결과(어느 라인을 몇 개로, 또는 취소) · 사유.
2. 읽기 전용 조회로 현재 값 기록(전표·라인·충당·ISSUE·수주 라인·회차) — 백업 JSON 으로 저장.
3. Data Reviewer 검토 → 사용자 승인(개발 창).
4. 아래 유형별 SQL 을 **한 트랜잭션**으로 실행(BEGIN … 확인 조회 … COMMIT). 쓰기마다 `master_change_log` 에
   「[일괄 정정 YYYY-MM-DD] P3-1a 건별 정정 SH-… (사유)」.
5. 정정 뒤 `revise_shipment_check(전표)` 가 그 라인에 사유를 내지 않는지 확인 → 이제 화면의 정정·취소가 정상 경로로 동작한다.
6. 월 점검(DATA_INTEGRITY §8) 묶음 1·3·4 다시 실행 — 예외 I·K 의 고정값이 바뀌면 해당 줄을 고친다.

## 유형별
### A — 충당 기록 없음(옛 추정 규칙을 사람이 확인해 충당 행으로 남긴다)
옛 엔진(2026-09-04)의 추정: **라인의 지정 회차(sched_id) → 납품완료가 있는 회차를 납기 최근순**. 이 순서를 그대로
쓰되, 사람이 회차 납품 기록(출고 리스트·거래명세서)과 맞는지 확인한 뒤 충당 행을 만든다.
```sql
-- 확인: 라인 수량, 지정 회차, 같은 수주 라인 회차의 납품완료·충당 합
select si.si_id, si.qty, si.sched_id, d.sched_id, d.due_date, d.qty, d.delivered_qty,
       (select coalesce(sum(a.qty),0) from shipment_allocations a where a.sched_id = d.sched_id) as alloc_sum
  from shipment_items si join so_delivery_schedule d on d.soi_id = si.soi_id
 where si.si_id = :si order by (d.sched_id = si.sched_id) desc, d.due_date desc;
-- 충당 행(회차별 수량은 확인한 값으로, Σ = 라인 수량, 회차마다 alloc_sum + 수량 ≤ delivered_qty)
-- 조건(r1 data LOW): 회차의 soi_id = 라인의 soi_id(076 M-2 — 다른 수주 라인의 회차 금지)
insert into shipment_allocations (si_id, sched_id, qty) values (:si, :sched, :q);
```
충당을 채우면 Σ충당 = 수량이 되어 `legacy_no_alloc` 에서 빠진다(목록은 조건과 함께 판정).

### B — 충당 > 납품완료(sched 151)
회차 납품완료와 두 전표의 충당 합이 다르다(1,732 vs 3,748). 실제 납품 기록으로 어느 쪽이 맞는지 정한 뒤
① 회차 `delivered_qty` 를 실제로 맞추거나 ② 잘못 붙은 충당 행을 실제 회차로 옮긴다(수량 무변경, sched_id 만).
```sql
update shipment_allocations set sched_id = :real_sched where alloc_id = :alloc;   -- ② 의 예
```
② 의 조건(r1 data LOW): 옮길 회차가 **같은 수주 라인 소속**(회차 soi_id = 라인 soi_id)이고, 옮긴 뒤 그 회차의
「Σ충당 ≤ delivered_qty」(옮기는 충당 수량 포함)가 성립해야 한다. 아니면 이 절차 밖 — Data Reviewer 와 따로 정한다.
정정 뒤 DATA_INTEGRITY §5 I 의 sched 151 고정값 줄을 지운다.

### C — 차감이 형제 라인에 몰림(가장 싸다 — 수량 무변경)
같은 수주 라인을 두 줄로 낸 전표에서 ISSUE 원장이 한 줄(ref_id)에 몰렸다. **ISSUE 행의 연결 라인만** 옮겨 라인별
순합을 라인 수량에 맞춘다(행 수량·LOT·날짜 무변경).
```sql
-- 확인: 라인별 ISSUE 순합
select ref_id, lot_number, sum(qty) from inventory_transactions
 where ref_table='shipment_items' and txn_type='ISSUE' and ref_id in (:si_a, :si_b) group by 1,2 order by 1,2;
-- 몰린 쪽 행 일부의 연결 라인만 형제 라인으로(행 단위, 수량·LOT·날짜 그대로)
update inventory_transactions set ref_id = :si_b where txn_id = :txn;
```
행 하나를 두 라인에 나눠야 맞는 경우(행 수량이 맞아떨어지지 않음)는 이 절차 밖 — Data Reviewer 와 따로 정한다.
정정 뒤 두 라인 모두 「ISSUE 순합 = −수량」·LOT 별 순차감 ≥ 0 이어야 한다.

## 전표·라인 삭제 SQL 주의(082 r2)
