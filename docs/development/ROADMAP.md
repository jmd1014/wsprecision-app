## 0. 운영 원칙

- 역할: 기획·검토 세션(계획·위험·Gate·승인) / 개발 세션(구현·테스트·리뷰 패키지) / Codex(읽기 전용 독립 리뷰) / 사용자(요구·최종 승인). AI 리뷰는 사용자 승인을 대체하지 않는다.
- 절차: 계획 → 사전 리뷰 → (Codex 계획 리뷰) → 구현 → 전체 pytest → Codex 구현 리뷰 → 수정·재검토 → 승인 → 사용자 확인 → push → 배포 후 확인. 변경 등급·백업·마이그레이션 규칙은 `AGENTS.md` 를 따른다.
- 대기열: 코드 작업은 한 번에 하나. **기능 1건 배포 → 로드맵 1단계 → 기능 1건** 으로 교대한다.
- 예외(대기열 맨 앞으로): **P0** = 불변식 3·4·9·11 위반 1건 이상(§P2a) / **HIGH** = 리뷰 HIGH 판정이고 운영 데이터에 닿는 것. 트래커에 "예외 처리" 꼬리표.
- ID: `P1`~`P5`(로드맵), `F-<이름>`(기능 트랙). 계획서 머리와 트래커 트랙 이름에 ID 를 쓴다.
